# Дорожная карта: от монолита к микроядру

Решение (октябрь 2026): AETERNA становится **настоящим микроядром**. Текущее состояние кода — в
[AUDIT.md](AUDIT.md). Каждый этап заканчивается проверкой в QEMU и VMware Workstation.

## Зачем эта система

ospab.os не пытается заменить Linux или Windows. Её идея — **ОС на правах доступа**:

- **Без root.** Нет всемогущего пользователя и `sudo`. Процесс может только то, на что у него есть
  дескриптор; первый процесс `seed` раздаёт минимум, и права нельзя получить «вообще», только
  конкретный ресурс.
- **Песочница по умолчанию (powerbox).** Программа стартует без доступа к файлам, сети и
  устройствам. Файл, выбранный пользователем в системном окне, программа получает одним
  дескриптором — и только его.
- **Без копирования (zero-copy).** Данные между драйверами, серверами и программами передаются
  дескрипторами общей памяти: пакет из сетевой карты, страница файла, буфер окна не копируются
  через ядро. Это снимает главный минус микроядра — цену передачи данных между серверами.

Позже на этом фундаменте: запись и воспроизведение процессов (вход процесса — только системные
вызовы и сообщения, поэтому его можно проиграть заново) и тензорная нагрузка как демонстрация
zero-copy (AVX-512/AMX, большие страницы).

Порядок: этап 0 (фундамент) → этап 3 (`seed`, вынос сервисов, rootless) → zero-copy в сетевом и
файловом серверах → powerbox.

## Что останется в ядре

Только то, что нельзя вынести:

- физические страницы и адресные пространства;
- потоки, планировщик, переключение контекста;
- IPC: синхронные сообщения (вызов/ответ) + асинхронные уведомления;
- передача и разделение памяти между процессами через IPC;
- прерывания, которые доставляются драйверам как уведомления;
- capability: у каждого процесса таблица дескрипторов, любое действие требует дескриптора.

Всё остальное — серверы в ring 3: драйверы, сеть (с OSTP), файловые системы, консоль, init.

## Этапы

### Этап 0. Фундамент ядра
Без этого ring 3 опасен. Пункты 1–6 из AUDIT.md.

1. ✅ Физический аллокатор с освобождением (bitmap), обнуление выделенных страниц.
2. ✅ Свой стек ядра у каждого потока; `TSS.RSP0` и стек SYSCALL переключаются вместе с потоком.
   Блокирующий системный вызов становится безопасным. Заодно: состояние FPU/SSE у каждой
   задачи, единое правило `swapgs` на входе/выходе ring 3, round-robin при равных приоритетах.
3. ✅ Кольцо не зависит от приоритета: `spawn_named` создаёт только потоки ядра,
   ring 3 — только `spawn_user_task`.
4. ✅ `copy_from_user` / `copy_to_user` во всех системных вызовах с указателями, SMEP + SMAP
   (если процессор умеет); `mmap`/`munmap` работают с памятью самого процесса.
5. Процесс как объект: ✅ адресное пространство, стек ядра и собственные страницы освобождаются
   при выходе; ✅ таблица дескрипторов (`core/object.rs`), ⬜ FD-таблица на процесс.
6. ⬜ Блокировки вместо `static mut`.
6а. ✅ XSAVE вместо FXSAVE: область по CPUID 0xD (с проверкой, иначе откат на FXSAVE), 64-байтовое
    выравнивание; тест — две задачи держат разные значения в ymm0/ymm15 при вытеснении.

Проверка: при загрузке выполняются тесты ring 3 (smoke, два процесса одновременно с блокировкой
в ядре, проверка указателей и `mmap`) и проверка, что после них не осталось занятых страниц.

### Этап 1. Программы в ring 3
7. ✅ ELF-загрузчик в ядре (`core/elf.rs`): сегменты с правами R-X / R-- / RW- и NX,
   стек с `argc`/`argv`/`auxv`.
8. ✅ `user/x86_64-unknown-oos.json` + **liboos** (`user/liboos`: `_start`, системные вызовы,
   куча через `mmap`, `print!`, panic). Программы собираются отдельным workspace `user/`.
9. ✅ Первая программа `user/hello` на Rust запускается из ядра при загрузке (пока встроена
   через `include_bytes!`; загрузка из файловой системы — этап 3).

### Этап 2. IPC и capability
10. ✅ Объекты ядра и дескрипторы с правами (READ/WRITE/DUP/TRANSFER): процесс, поток, канал,
    уведомление, ответ (Reply); ✅ память, MMIO, прерывание, порты, ресурс DMA (пункты 12–13);
    ⬜ адресное пространство как объект.
11. ✅ Синхронный IPC вызов/ответ с передачей дескрипторов, блокирующий приём без цикла ожидания,
    уведомления. Описание: [docs/ru/syscall-abi.md](docs/ru/syscall-abi.md); обёртки — `liboos::ipc`;
    тест — `user/ipcsrv` + `user/ipcclient` (запуск: параметр ядра `selftest=ipc`).
12. ✅ Разделяемая память через дескрипторы: объект MemoryRegion (`mem_create`/`mem_map`/`mem_unmap`,
    права MAP/EXEC/PHYS, NX по умолчанию, W^X), страницы со счётчиком ссылок (дескрипторы +
    отображения), освобождаются при выходе процесса; DMA — `mem_create_contig` только с дескриптором
    Resource(DMA). SMR с сырыми физическими адресами, `dma_alloc`, сырой ввод-вывод в порты
    (60/61/62) и `vfs_register` убраны из системных вызовов. Тест — `user/memtest` (`selftest=mem`).
13. ✅ Оборудование как дескрипторы: Interrupt (линия IRQ → Notification, маска до `irq_ack`),
    IoPortRange (карта разрешений ввода-вывода в TSS), MmioRegion (отображение без кэша). Создаёт
    только корень (ядро при загрузке), драйвер получает начальными дескрипторами. Проверка —
    драйвер COM2 в ring 3 (`user/uartdrv`, `selftest=mem`, нужен второй `-serial`). ⬜ MSI.

### Этап 3. Вынос сервисов из ядра
Порядок — от простого к сложному, по одному, ядро после каждого шага остаётся рабочим:

14. `seed` — первый настоящий процесс, запускает остальных и перезапускает упавших. Единственный
    держатель корневых прав: создаёт объекты железа и раздаёт их, а лишние после старта сбрасывает.
15. Консоль: клавиатура + фреймбуфер → сервер консоли. `plum` становится программой.
    С этого момента в системе нет root: оболочка — обычный процесс со своими дескрипторами.
16. Хранилище: AHCI/NVMe → драйверы-серверы; VFS → сервер файловой системы. Страницы файлов
    отдаются клиентам дескрипторами памяти (zero-copy).
17. Сеть: драйверы NIC → серверы; сетевой стек → сетевой сервер. Пакеты передаются буферами
    общей памяти, без копирования между драйвером, стеком и приложением.
18. Звук, мышь, остальное. DOOM — обычная программа.
19. В ядре не остаётся драйверов (кроме таймера, контроллера прерываний и отладочного serial).
19а. Powerbox: программы стартуют без доступа к файлам и сети; системное окно выбора файла
     выдаёт программе дескриптор на один файл.

### Этап 4. Свой загрузчик
20. UEFI-загрузчик на Rust вместо Limine; образ диска GPT + FAT32 собирается без WSL.

### Этап 5. OSTP
21. `ostp-core` в режиме `no_std + alloc`.
22. OSTP как туннельный интерфейс в сетевом сервере.

## Отложено
- SMP (несколько ядер процессора) — после этапа 2.
- Полноценный `std` для программ — после этапа 3.
