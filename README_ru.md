**ospab.os** — закрытая, целостная операционная система, написанная с нуля на Rust.
Её ядро называется **AETERNA**. Система не стремится к совместимости с Linux или Windows:
ядро, драйверы, сетевой стек, оболочка и утилиты пишутся вместе и проектируются как одно целое.
ospab.os — часть экосистемы ospab, в ней будет нативная низкоуровневая поддержка транспорта
[OSTP](https://github.com/ospab/ostp).

> **Статус: исследовательская система в процессе переделки.** Ниже всё разделено на
> *что работает сейчас* и *куда идём*. Ядро перестраивается из монолита с одним адресным
> пространством в настоящее микроядро. Честное состояние кода — в [AUDIT.md](AUDIT.md),
> план — в [ROADMAP.md](ROADMAP.md).

## Что работает сейчас

| Область | Состояние |
|---|---|
| Загрузка | Протокол Limine, гибридный BIOS/UEFI ISO; работает в QEMU и VMware Workstation |
| Процессор | GDT + TSS, IDT, APIC-таймер (1 кГц), вытесняющий планировщик, SSE |
| Память | 4-уровневые таблицы страниц, адресное пространство у каждой задачи, куча ядра |
| Ring 3 | SYSCALL/SYSRET работает; один тестовый процесс проходит туда и обратно (этап 1) |
| Хранилище | ATA PIO, AHCI, NVMe; GPT; установщик на диск (GPT + FAT32 + LFN) |
| Файловая система | VFS + RamFS с отложенным сохранением на диск |
| Сеть | RTL8139, RTL8169, e1000, virtio-net; ARP, IPv4, ICMP, UDP, TCP, DHCP, DNS, SNTP, TLS-клиент |
| Звук | AC97, ES1371, Intel HDA |
| Ввод / видео | Клавиатура и мышь PS/2, UEFI-фреймбуфер, VMware SVGA |
| Программы | оболочка `plum`, редактор `grape`, пакетный менеджер `tomato`, init `seed`, coreutils, DOOM |

**Важно:** кроме тестового процесса ring 3, всё перечисленное сейчас работает в ring 0, в одном
адресном пространстве. Изоляции процессов пока нет, модель capability не применяется.

## Куда идём

- **Микроядро.** В ядре остаются только адресные пространства, потоки, планирование, IPC,
  прерывания и capability. Драйверы, сетевой стек, файловые системы и консоль становятся
  изолированными серверами в пространстве пользователя и общаются через IPC. Упавший драйвер
  перезапускается, а не роняет ядро.
- **Capability вместо root.** Процесс может трогать только то, на что у него есть дескриптор.
- **Свой загрузчик.** Небольшой UEFI-загрузчик на Rust вместо Limine.
- **liboos** — рантайм для программ и Rust-target (`x86_64-unknown-oos`) для сборки программ под ospab.os.
- **Нативный OSTP** в сетевом сервере: вся система может ходить через OSTP-туннель.

## Сборка

Нужно: Rust nightly с `rust-src`, а для ISO — `xorriso`, `mtools`, `mkfs.vfat`
(на Windows ISO собирается из WSL).

```bash
./build.sh kernel   # только ядро — быстрая проверка компиляции
./build.sh          # ядро + DOOM + загрузочный гибридный ISO в isos/
```

## Запуск

```bash
qemu-system-x86_64 -cdrom isos/ospab-os-v2-N.iso -m 512M -serial stdio
```

VMware Workstation: подключите ISO как CD/DVD. Диагностика ядра идёт в последовательный порт
(COM1), терминал рисуется на фреймбуфере.

## Структура проекта

```
arch/x86_64/   настройка CPU, прерывания, TSS, фреймбуфер, serial, клавиатура, мышь, связка с Limine
core/          планировщик, системные вызовы, IPC, capability
mm/            физические страницы, таблицы страниц, куча ядра
drivers/       хранилище, PCI, звук, GPU
net/           драйверы сетевых карт и сетевой стек
vfs/           VFS, RamFS, синхронизация с диском
src/           точка входа ядра, терминал, установщик, связка с DOOM
userland/      grape, tomato, seed (пока компилируются в ядро)
doom_engine/   doomgeneric + минимальная libc
```
