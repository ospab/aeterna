# Установка

Запустите `install` в Live-системе или выберите **ospab.os Installer** в меню загрузки.
Установщик — полноэкранный мастер: приветствие → диск → параметры → подтверждение → установка →
готово. Esc возвращает назад; Esc или `q` выходит с любой страницы, пока на диск ничего не записано.

Установленная система грузится только через UEFI, поэтому машина (или ВМ) должна работать с
прошивкой UEFI.

## Режим 1: стереть диск

Диск размечается заново целиком:

| Раздел | Содержимое |
|---|---|
| EFI System Partition (FAT32) | `\EFI\BOOT\BOOTX64.EFI` (ospab-boot), `\boot\KERNEL`, `\boot\ospab.cfg` |
| AETERNA | сохранённый изменяемый слой файловой системы |

Вы выбираете диск, размер EFI-раздела, имя компьютера и язык, затем подтверждаете вводом `yes`.
Установщик копирует файлы, проверяет их обратным чтением (9 проверок) и предлагает **Reboot now**.

## Режим 2: установить рядом с другими системами

Для диска, на котором уже стоят Windows и/или Linux. Установщик:

- читает и проверяет обе копии GPT и показывает существующие разделы;
- создаёт **один** новый раздел `AETERNA` в самом большом свободном участке;
- добавляет папку `\EFI\ospab\` (загрузчик, конфиг, ядро) в **существующий** FAT32 EFI-раздел;
- никогда не двигает, не меняет размер и не перезаписывает чужие разделы и не трогает
  `\EFI\Microsoft`, `\EFI\BOOT` и папки других систем;
- никогда не пишет переменные NVRAM UEFI.

Перед записью он показывает пробный прогон со списком всех диапазонов секторов и файлов, которые
будут записаны; подтверждение — ввод `install`. Каждая запись сверяется с этим списком.

Установщик отказывает с объяснением и ничего не пишет, если диск размечен только MBR, резервная
копия GPT повреждена, нет свободного места или EFI-раздела, EFI-раздел не FAT32 или папка
`\EFI\ospab` уже существует. Чужие разделы он не уменьшает: сначала освободите место средствами
«Управления дисками» Windows или программой разметки в Linux.

### Как загрузить систему, установленную рядом

Прошивка не знает о новом загрузчике, поэтому выберите один из способов:

- **Меню загрузки прошивки**: «Boot from file» → EFI-раздел → `\EFI\ospab\OSPABLDR.EFI`.
- **GRUB** (из вашего Linux): добавьте в `/etc/grub.d/40_custom` и выполните `update-grub`:
  ```
  menuentry "ospab.os" {
      insmod part_gpt
      insmod fat
      search --file --set=root /EFI/ospab/OSPABLDR.EFI
      chainloader /EFI/ospab/OSPABLDR.EFI
  }
  ```
- **efibootmgr** (из Linux) создаёт пункт в меню прошивки; диск и номер EFI-раздела возьмите из
  `lsblk`:
  ```
  sudo efibootmgr -c -d /dev/sdX -p N -L ospab.os -l '\EFI\ospab\OSPABLDR.EFI'
  ```

## После установки

- Отключите ISO, иначе прошивка снова загрузится с CD.
- В логе загрузки будет `Boot loader: ospab-boot`, а строка `Persistence:` покажет область сохранения.
- Изменения файловой системы пишутся на диск командой `sync` и автоматически примерно раз в 10 секунд.

## Известные ограничения

- Диски с логическими секторами 4096 байт в режиме «рядом» не поддерживаются.
- Если в машине есть и SATA-, и NVMe-диски, сохранение идёт на SATA.
- В VMware последний шаг «Reboot now» может подвесить ВМ; выключить и включить её безопасно —
  установка к этому моменту уже завершена.
