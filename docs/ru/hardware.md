# Оборудование

ospab.os разрабатывается и тестируется в VMware Workstation и QEMU. На реальном железе её не
проверяли.

| Класс | Поддерживается | Примечания |
|---|---|---|
| Прошивка | UEFI (x86-64) и BIOS, обе через ospab-boot | ISO и установленный диск грузятся в обоих режимах; «установить рядом» требует UEFI |
| Процессор | x86-64; использует SSE2, XSAVE/AVX, NX, SMEP/SMAP, RDRAND, если они есть | одно ядро (SMP пока нет) |
| Диски | ATA PIO (IDE), AHCI (SATA), NVMe, virtio-blk | первый NVMe-контроллер, namespace 1; секторы 512 байт и 4 КБ |
| Сеть | семейство Intel e1000, RTL8139, RTL8169/8111, virtio-net, AMD PCnet (vlance в VMware), VMware vmxnet3 | только IPv4 |
| Звук | Intel HDA, AC97, Ensoniq ES1371/ES1373/CT5880, ES1370 | 16 бит стерео, DMA с опросом |
| Ввод | клавиатура и мышь PS/2, USB-клавиатура и мышь через xHCI (включая хабы), абсолютная мышь VMware | нет EHCI/UHCI и горячего подключения |
| Видео | фреймбуфер UEFI GOP и BIOS VBE 2.0 (32 бита, линейный), VMware SVGA II | программная отрисовка |
| Платформа | ACPI (выключение, перезагрузка, кнопка питания, MADT), PCI, CMOS RTC, I/O APIC, MSI/MSI-X, таймер local APIC, PIT, запасной вариант 8259 | один процессор; нет интерпретатора AML |
| Связь с хостом | backdoor VMware: буфер обмена, абсолютная мышь, autofit (GuestRPC) | |

## Рекомендуемые настройки VMware

См. таблицу в разделе [Первые шаги](getting-started.md#vmware-workstation). Коротко: Other 64-bit,
UEFI без Secure Boot, USB 3.x, разрешённые копирование и вставка, без SCSI BusLogic.

## Режимы экрана и autofit

Первый режим выставляет загрузчик (ключ `resolution` в его конфиге; на ноутбуке он берёт режим
GOP, например 1920x1080). После загрузки ядро умеет менять режим на лету только на адаптере
VMware SVGA II (VMware и QEMU с `-vga vmware`). На других машинах остаётся режим загрузки, и
`display list` показывает только его.

| Параметр | Поведение |
|---|---|
| Режимы | любой WxH от 640x480 до предела устройства и его видеопамяти (для 32 bpp нужно `W*H*4` байт); ширина округляется вниз до кратной 8 (иначе адаптер сдвигает строки: 1366 становится 1360) |
| Заготовки | 1024x768, 1280x720 (`hd`), 1280x800, 1280x1024, 1366x768, 1600x900, 1920x1080 (`fullhd`), 2560x1440 (`2k`), 3840x2160 (`4k`); в списке только те, что помещаются |
| Переключение | `display set fullhd` или Settings > Display. Адрес, размер и шаг фреймбуфера перепрограммируются, консоль перерисовывается, рабочий стол раскладывается заново |
| Сохранение | `/etc/display.conf` (`mode=`, `auto=`, `scale=`), применяется после старта консоли |
| Шрифт консоли | 8x16 с целым масштабом: автоматически 2x от ширины 2560 px (`display scale 1\|2\|auto`) |

Autofit заставляет гостя следовать за окном VMware, как это делает VMware Tools. Ядро открывает
каналы GuestRPC через backdoor (порт 0x5658, команда 0x1E). По каналу RPCI оно сообщает хосту
`tools.capability.resolution_set 1`, а по каналу TCLO отвечает `OK ` на `Resolution_Set <w> <h>`.
Каналы опрашиваются из цикла простоя консоли и цикла рабочего стола, не чаще чем раз в 100 мс.
Под VMware autofit включён по умолчанию. `display set` его выключает, `display auto` включает
снова. Нужна опция VMware View > Autofit Guest; вне VMware autofit ничего не делает. Без VMware
Tools хост может вообще не присылать `Resolution_Set`, и `display set` всё равно работает. В
последовательном логе каждый шаг помечен тегом `[DISPLAY]` (открытие канала, возможности, запросы,
смена режима).

## Диагностика

Каждый драйвер пишет в первый последовательный порт с меткой вроде `[AHCI]`, `[NVME]`, `[XHCI]`,
`[HDA]`, `[e1000]`. Чтобы читать лог, добавьте в VMware последовательный порт с выводом в файл. В
QEMU используйте `-serial stdio` или `-serial file:boot.log`.
