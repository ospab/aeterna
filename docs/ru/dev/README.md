# Разработка для ospab.os

Руководство для тех, кто хочет написать код для ospab.os: программу, игру, драйвер, команду
оболочки или изменение в ядре. Оно рассчитано на человека, который уже запускал систему
(см. [Первые шаги](../getting-started.md)) и знает Rust.

## Что можно написать

| Что | Где лежит | Где работает | Состояние |
|---|---|---|---|
| Программа или пакет | `apps/<имя>/` | ring 3 | Работает. Обычный способ добавить ПО. |
| Игра или эмулятор | `apps/<имя>/`, при желании с крейтом `<имя>-core` | ring 3 | Работает. Полный экран, сырая клавиатура, звук. Примеры: `drift`, `beeb`. |
| GUI-приложение | `apps/<имя>/` поверх `gui/` (`oos-ui`) | рабочий стол в ядре; сборка для ring 3 пока рисует только в память | Частично. См. [GUI-приложения](../gui-apps.md). |
| Скрипт оболочки | любой файл в `$PATH` или `bash file.sh` | оболочка (ring 0) | Работает. См. [Оболочка](../shell.md). |
| Команда оболочки | `src/userspace/axon/`, `src/userspace/plum/`, `src/terminal.rs` | ring 0 | Работает. Нужна пересборка ядра. |
| Драйвер | `drivers/`, `net/`, `src/xhci/` | ring 0 | Работает. Нужна пересборка ядра. |
| Подсистема ядра | `core/`, `mm/`, `vfs/`, `arch/`, `fs/aeternafs/` | ring 0 | Работает. |
| Загрузчик | `boot/` | прошивка, затем long mode | Работает. См. [Загрузка](../boot.md). |
| Утилита для хоста | `tools/` | ваш ПК | `tmt` (пакеты) и `oosfs` (образы AeternaFS). |

## Сколько работает в ring 0

Разберитесь с этим до того, как выберете, куда класть код.

Сейчас ospab.os — монолитное ядро, которое переделывают в микроядро. Оболочка (`plum`), утилиты
(`ls`, `grep`, ...), редактор, `tomato`, `curl`, консоль, все драйверы, сетевой стек, файловая
система и рабочий стол работают внутри ядра, в ring 0. Ошибка в любой из этих частей может
уронить машину.

В ring 3 сегодня работают:

- программы из пакетов `.tmt` (всё, что лежит в `apps/`);
- тестовые программы из `user/`, которые ядро запускает при самопроверке во время загрузки.

Механизмы для выноса остального в ядре уже есть: дескрипторы с правами, IPC, общая память,
прерывания, порты ввода-вывода и память устройств в виде дескрипторов. Драйвер UART в ring 3
(`user/uartdrv`) это доказывает. Сами службы пока не вынесены. Это этап 3
[дорожной карты](../../../ROADMAP.md): `seed` как первый настоящий процесс, затем консоль,
хранилище, сеть, звук и так далее, по одному.

Что это значит для вас:

- Программа в `apps/` изолирована. Падение убивает только её процесс, оболочка печатает код
  завершения. Это безопасное место для экспериментов.
- Программа ring 3 сейчас видит малую часть системы: файлы по пути, консоль, экран, сырую
  клавиатуру, звук, часы, память. У неё нет сети, нет списка каталога, нет запуска других
  программ и нет переменных окружения. Чего не хватает, перечислено в
  [справочнике liboos](liboos.md). Если нужно что-то из этого, работа идёт в ядре:
  [Работа с ядром](kernel-hacking.md).
- Код в `drivers/`, `net/`, `vfs/` и `src/userspace/` работает в ring 0. Относитесь к нему как к
  ядру: никаких паник на плохом вводе, соблюдайте [правила блокировок](../../en/kernel.md)
  (на английском).
