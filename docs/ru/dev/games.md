# Игры

Игра или эмулятор для ospab.os — обычная программа ring 3, которая занимает весь экран. Она
рисует пиксели в кадровый буфер, читает сырые события клавиатуры, отдаёт звук ядру и сама
отсчитывает время. Здесь показано, как это делается, на двух готовых примерах. Сначала прочитайте
[Первую программу](first-program.md) и [справочник liboos](liboos.md).

Примеры:

- `apps/drift` и `apps/drift-core`: игра про торговлю и бои в космосе с программным 3D-рендером.
  [Описание](../../en/drift.md) (на английском).
- `apps/beeb` и `apps/beeb-core`: эмулятор BBC Micro. [Описание](../beeb.md).
- `apps/gfxtest`: самая маленькая проверка экрана, клавиатуры и часов. `apps/tone`: самая
  маленькая проверка звука.

## Отделите игру от оболочки

В обоих больших примерах два крейта:

- `<имя>-core` — библиотека `no_std` с симуляцией, рендером и меню. Она рисует в обычный буфер
  пикселей (`0x00RRGGBB`), принимает абстрактные действия как ввод и заполняет буфер отсчётов
  для звука. Системных вызовов в ней нет.
- `<имя>` — тонкая программа ring 3: аргументы, файлы, кадровый буфер, клавиатура, часы, звуковой
  поток.

Ядро собирается и тестируется на вашем ПК, скриншоты пишутся файлами, так что большинство ошибок
находится без ВМ. См. [Тестирование](testing.md). Оба крейта добавьте в `members` в
`apps/Cargo.toml`. Манифест пакета нужен только для программы.

## Устройство программы

```
взять экран  ->  включить сырую клавиатуру  ->  открыть звук (необязательно)
цикл:
    прочитать события клавиш
    выполнить симуляцию (фиксированный шаг)
    подмешать звук
    нарисовать в задний буфер в ОЗУ
    скопировать задний буфер на экран, flush
    дождаться следующего кадра
выключить сырую клавиатуру  ->  отдать экран
```

Всегда отменяйте то, что сделали, на выходе, в том числе на путях ошибок. Если программа
заканчивается любым способом, ядро само освобождает экран, клавиатуру и звуковые потоки, но
аккуратный выход позволяет консоли сразу перерисоваться и печатает ваше сообщение на нужном
месте.

Ниже полный каркас. Он двигает квадрат стрелками, пищит у стен и выходит по Esc. Собирается как
есть с текущим liboos.

```rust
// SPDX-License-Identifier: AGPL-3.0-only
//! Skeleton of a full-screen game: fixed 60 Hz simulation, back buffer, raw keyboard, sound.
#![no_std]
#![no_main]

extern crate alloc;

use alloc::vec;
use alloc::vec::Vec;
use liboos::audio::Audio;
use liboos::println;
use liboos::screen::{self, Framebuffer};

liboos::entry!(main);

const STEP_NS: u64 = 16_666_667; // simulation step: 60 Hz
const MAX_FRAME_NS: u64 = 250_000_000; // never simulate more than 250 ms at once
const W: usize = 320; // internal resolution
const H: usize = 200;

struct State {
    x: i32,
    dx: i32,
    left: bool,
    right: bool,
    beep: bool,
    quit: bool,
}

impl State {
    fn update(&mut self) {
        let want = (self.right as i32) - (self.left as i32);
        self.x = (self.x + want * 3 + self.dx).clamp(0, W as i32 - 16);
        if self.x == 0 || self.x == W as i32 - 16 {
            self.beep = true;
        }
    }

    fn render(&self, back: &mut [u32]) {
        back.fill(0x00101830);
        for y in 90..106 {
            for x in self.x as usize..self.x as usize + 16 {
                back[y * W + x] = 0x00FFA000;
            }
        }
    }
}

/// Copy the back buffer to the screen, scaled by an integer factor and centred.
fn present(fb: &Framebuffer, px: &mut [u32], back: &[u32], scale: usize) {
    let stride = fb.stride();
    let x0 = (fb.width as usize - W * scale) / 2;
    let y0 = (fb.height as usize - H * scale) / 2;
    for y in 0..H {
        for k in 0..scale {
            let row = &mut px[(y0 + y * scale + k) * stride + x0..][..W * scale];
            for (i, d) in row.iter_mut().enumerate() {
                let c = back[y * W + i / scale];
                *d = fb.rgb((c >> 16) as u8, (c >> 8) as u8, c as u8);
            }
        }
    }
}

/// Keep about 90 ms of sound queued. Samples the kernel did not take stay in `pending`.
fn feed_audio(a: &Audio, state: &mut State, phase: &mut u32, pending: &mut Vec<i16>) {
    if !pending.is_empty() {
        let n = a.write(pending);
        pending.drain(..n);
        if !pending.is_empty() {
            return;
        }
    }
    let target = a.rate() as usize * 90 / 1000;
    let queued = a.queued();
    if queued >= target {
        return;
    }
    let frames = target - queued;
    let mut buf = vec![0i16; frames];
    for s in buf.iter_mut() {
        if state.beep {
            *s = if (*phase / 55) % 2 == 0 { 5000 } else { -5000 };
            *phase += 1;
            if *phase > 4800 {
                *phase = 0;
                state.beep = false;
            }
        }
    }
    let n = a.write(&buf);
    pending.extend_from_slice(&buf[n..]);
}

fn main(_args: liboos::Args) -> i32 {
    let fb = match screen::acquire() {
        Ok(f) => f,
        Err(e) => {
            println!("cannot get the screen (error {})", e);
            return 1;
        }
    };
    if screen::kbd_raw(true) < 0 {
        screen::release();
        println!("the keyboard is in use");
        return 1;
    }
    let scale = (fb.width as usize / W).min(fb.height as usize / H).max(1);
    let px = unsafe { fb.pixels() };
    px.fill(fb.rgb(0, 0, 0));
    let mut back = vec![0u32; W * H];
    let audio = Audio::open(48000, 1).ok();
    let mut pending: Vec<i16> = Vec::new();
    let mut phase = 0u32;

    let mut st = State { x: 100, dx: 0, left: false, right: false, beep: false, quit: false };
    let mut last = screen::clock_ns();
    let mut acc = 0u64;
    while !st.quit {
        let now = screen::clock_ns();
        acc += (now - last).min(MAX_FRAME_NS);
        last = now;

        while let Some(ev) = screen::key_event() {
            match (ev.code, ev.extended) {
                (0x01, _) => st.quit = true,
                (0x4B, true) => st.left = ev.pressed,
                (0x4D, true) => st.right = ev.pressed,
                _ => {}
            }
        }
        while acc >= STEP_NS {
            st.update();
            acc -= STEP_NS;
        }
        if let Some(a) = &audio {
            feed_audio(a, &mut st, &mut phase, &mut pending);
        }
        st.render(&mut back);
        present(&fb, px, &back, scale);
        screen::flush();

        // wait for the next frame: sleep while there is time, spin the last milliseconds
        let target = now + STEP_NS;
        loop {
            let t = screen::clock_ns();
            if t >= target {
                break;
            }
            if target - t > 12_000_000 {
                screen::sleep_ms((target - t) / 1_000_000 - 10);
            } else {
                core::hint::spin_loop();
            }
        }
    }
    screen::kbd_raw(false);
    screen::release();
    0
}
```

## Время: фиксированный шаг

Гоняйте симуляцию с фиксированной частотой, а рисуйте так часто, как получится. Тогда игра ведёт
себя одинаково на быстрой и на медленной машине, и её можно тестировать.

- Читайте `screen::clock_ns()` раз в кадр, прибавляйте прошедшее время к накопителю и вызывайте
  `update()` по разу на каждый целый шаг в нём.
- Ограничивайте прошедшее время (в каркасе 250 мс), чтобы после остановки не выполнялись сотни
  шагов подряд.
- `drift-core` шагает с частотой 30 Гц и берёт время кадра только для эффектов рисования.
  `beeb-core` выполняет ровно один эмулируемый кадр в 20 мс на каждый реальный кадр.
- Не берите `uptime_ticks` как игровое время: у него разрешение 10 мс.

## Ожидание следующего кадра

Вертикальной синхронизации и переключения страниц нет. Ждать приходится самому.

- `sleep_ms` отдаёт процессор оболочке и другим задачам, но ядро будит вас по своему такту 100 Гц,
  так что вы можете опоздать до 10 мс. Спите только на ту часть ожидания, которая больше примерно
  12 мс, минус 10 мс, а остаток крутитесь на `clock_ns`. Так делают каркас и `beeb`.
- `drift` в цикле ожидания вызывает `liboos::yield_now()`. Процессор остаётся занят, но
  дедлайн никогда не проспится.
- Планируйте кадры от бегущей цели (`next += FRAME_NS`), а не «сейчас плюс кадр», иначе частота
  кадров поплывёт. Если вы сильно отстали (`beeb` допускает 5 кадров), сбросьте цель на «сейчас».
  Не пытайтесь нагонять: теряйте время.
- `sleep_ms`, `key_event` и `flush` ещё и проверяют Ctrl+C. Хотя бы один из них должен быть в
  цикле.
- В QEMU без аппаратного ускорения гость медленный. Игра, которая идёт на 60 Гц в VMware, в TCG
  может идти на 15 Гц. Проверяйте в обоих и замеряйте.

## Экран

- `screen::acquire()` может не удаться. Напечатайте ошибку и верните ненулевой код. См.
  [справочник liboos](liboos.md#экран).
- Берите настоящие `fb.width` и `fb.height`. Режим зависит от ВМ и от команды `display`. Выберите
  внутреннее разрешение, затем масштабируйте целым коэффициентом (`scale = min(fb.width / W,
  fb.height / H)`) и центрируйте. `drift` берёт разрешение из `-r N` (1/N экрана); у `beeb` есть
  `-scale`.
- Рисуйте в буфер в обычной памяти (задний буфер), а на экран (`fb.pixels()`) копируйте один раз
  за кадр, строка за строкой. Кадровый буфер — некэшируемая память устройства: запись строки
  через `copy_from_slice` быстрая, а чтение оттуда и рисование прямо в него по пикселям — медленное.
  `drift` и `beeb` размножают строки развёртки через `copy_within` на самом экране; это чтение
  оттуда. Если узким местом стала запись на экран, сначала собирайте масштабированные строки в
  ОЗУ.
- Проверьте формат пикселя один раз. Если `red_shift == 16 && green_shift == 8 && blue_shift == 0`,
  ваши значения `0x00RRGGBB` можно копировать как есть (в `drift` есть такой быстрый путь). Иначе
  преобразуйте через `fb.rgb`.
- На экране один буфер. Переключения страниц нет, возможны разрывы кадра. Делайте копирование
  коротким (один проход по строкам) и вызывайте `flush()` сразу после него. На VMware SVGA II
  `flush` важен: без него окно не обновится.
- `beeb` сравнивает каждую строку источника с прошлым кадром и пропускает неизменившиеся. Это
  помогает для двумерной картинки, которая меняется мало.
- После `acquire` залейте весь экран чёрным, чтобы текст консоли не просвечивал вокруг картинки.

## Ввод

- `kbd_raw(true)` вызывайте после получения экрана, `kbd_raw(false)` — перед тем, как его
  отдать.
- Читайте все ожидающие события каждый кадр: `while let Some(ev) = key_event()`.
- Ведите таблицу нажатых клавиш, обновляйте её по `pressed`, а симуляция пусть читает таблицу. Не
  двигайте объекты только в момент прихода события.
- Отображайте скан-коды в собственный `enum` действий в одной функции (`map_key` в
  `apps/drift/src/main.rs`, `apps/beeb/src/keymap.rs`). Таблица скан-кодов — в справочнике liboos.
- Стрелки приходят с `extended = true`. Те же коды с `extended = false` — цифровая клавиатура.
- Предусмотрите клавишу выхода (Esc или F12). Ctrl+C работает всегда, но не даёт сохраниться и
  прибраться.
- Интерфейса мыши для ring 3 нет. Игры управляются только с клавиатуры.

## Звук

- Открывайте поток после экрана, ошибку игнорируйте и продолжайте молча.
- Берите 48000 Гц стерео, если синтезируете (`drift`), или моно, если источник моно (`beeb`).
  22050 Гц вдвое сокращает работу для простых эффектов; ядро пересчитает частоту.
- В каждом кадре смотрите на `queued()`. Если оно ниже цели (от 60 до 100 мс), сформируйте
  недостающие кадры. Никогда не формируйте безусловно «время одного кадра»: при колебаниях частоты
  кадров буфер будет то расти, то пустеть. В этом вся суть темпа.
- `write` не блокируется и может принять меньше, чем вы предложили. Остаток сохраните до
  следующего кадра, как делает `feed_audio`.
- Если игра сильно отстала, а очередь уже длинная (у `beeb` — больше 100 мс), выбросьте отсчёты
  этого кадра, а не наращивайте задержку.
- На паузе игра пишет тишину или перестаёт писать: пустой поток играет тишину, больше ничего не
  нужно.
- Задержка от события в игре до звука — это очередь плюс около 60 мс в устройстве. Если важна
  точность эффектов, держите очередь короткой.
- Перед выходом вызовите `drain()`, если последний звук должен прозвучать.

## Память

- Куча начинается с 4 МиБ и растёт целыми регионами не меньше 8 МиБ. Одно выделение — не больше
  примерно 64 МиБ. См. [справочник liboos](liboos.md#куча).
- Большие буферы выделяйте один раз при старте (`vec![0u32; W * H]`, текстуры, сетки) и
  используйте повторно. В цикле кадра не выделяйте. Освобождённая память остаётся в процессе, а
  первое подходящее место при смешанных размерах фрагментирует регионы.
- Проверьте, что память есть, прежде чем выбирать размер. `Vec::try_reserve_exact(n)` возвращает
  ошибку вместо аварийного завершения. `drift` так и выбирает размер интерфейса: ему нужно около
  12 МиБ плюс `w * h * 4` байтов, он пробует родной размер и откатывается на 1/2, 1/3, 1/4.
- В ВМ должно хватать ОЗУ. [drift](../../en/drift.md) называет около 32 МиБ кучи для своего
  1080p по умолчанию.
- Стек — 64 КиБ. Большие массивы кладите в кучу.

## Скорость программного рендера

Интерфейса к GPU нет, а сгенерированный код не использует SIMD сверх SSE2 (цель собирается с
`+sse,+sse2`). В `drift` и `beeb` помогло следующее:

- Рисуйте во внутреннем разрешении поменьше и растягивайте. Цена копирования на экран — это
  `fb.width * fb.height * 4` байтов за кадр при масштабе 1:1 (8 МиБ в 1080p).
- Замеряйте каждый кадр через `clock_ns`, держите скользящее среднее и понижайте качество, когда
  слишком медленно (`drift` снижает качество на ступень, когда среднее больше 38 мс). Сохранённую
  настройку при этом не меняйте.
- Берите `f32` и целочисленную математику. Арифметика работает на SSE2, но `sin`, `cos`, `sqrt` и
  `powf` в `core` нет: пишите небольшие приближения или таблицы (в `drift-core` свои).
- Держите внутренние циклы свободными от проверок границ и вызовов, которые не встраиваются.
  Итерируйте по срезам через `iter_mut().zip(...)`, работайте целыми строками, используйте `fill`
  и `copy_from_slice`.
- Рабочая область собирается с `opt-level = "s"` и LTO. Если крейт-ядро медленнее, чем хочется,
  попробуйте `[profile.release.package.<крейт-ядро>] opt-level = 3` в `apps/Cargo.toml` и
  измерьте размер и скорость.
- Не делайте то, что не изменилось: неизменные строки (`beeb`), небо или текстуру, которую
  рисуют один раз, проход свечения вполовину меньшего размера.
- Проверяйте медленный путь: запускайте в QEMU с `-accel tcg`. Если там играбельно, то везде
  нормально.

## Сохранения и настройки

Файлы работают так, как описано в справочнике liboos: абсолютные пути, чтения каталога нет.
`drift` пишет `drift-slotN.sav` и `drift.cfg` в `/home`, а при неудаче в `/tmp`, и читает из
тех же каталогов. `O_WRITE` очищает существующий файл, так что в сохранении не остаются хвосты
от более длинного. На установленной системе файлы попадают на диск через несколько секунд после
последнего изменения (AeternaFS делает коммит из потока ядра, в том числе пока идёт игра).
Программа должна писать, когда меняется что-то важное, а не только при выходе.
`beeb` читает `/etc/beeb.conf` для значений по умолчанию.

Не кладите в репозиторий чужие игровые данные. `beeb` просит у пользователя ROM MOS и образы
дисков; `drift` делает всё сам. См. [Как внести изменения](../../../CONTRIBUTIONS_ru.md).
