# Загрузка

Полное описание загрузчика ospab-boot (UEFI и BIOS, формат `ospab.cfg`, меню) пока есть только на
английском: [docs/en/boot.md](../en/boot.md). Здесь переведён раздел об обновлении системы и
откате.

## Обновление системы

`tomato upgrade` ([Пакеты](packages.md), «Обновление системы») кладёт новое ядро рядом со старым
на ESP и включает счётчик загрузок. Файлы лежат в каталоге, где находится `ospab.cfg` (`/boot`
или `/EFI/ospab`):

| Файл | Значение |
|---|---|
| `KERNEL` | ядро, которое грузят пункты меню |
| `KERNEL.OLD` | прежнее ядро (последнее исправное) |
| `KERNEL.NEW` | есть только во время обновления |
| `UPDATE.ST` | счётчик загрузок, ровно 512 байт |
| `BOOTX64.OLD` / `OSPABLDR.OLD` | прежний загрузчик, для ручного восстановления |

В `ospab.cfg` добавляется пункт "ospab.os (previous)" (`kernel = .../KERNEL.OLD`). Его всегда
можно выбрать в меню.

### Счётчик загрузок и автоматический откат

`UPDATE.ST` — текст, дополненный нулями до 512 байт. Поэтому загрузчик перезаписывает его на месте
и не трогает FAT:

```
ospab-update 1
pending=1
tries=2
failed=0
kernel=/boot/KERNEL
old=/boot/KERNEL.OLD
version=1.1.0.191
previous=1.1.0.190
```

Оба загрузчика делают одно и то же (`boot/common/update.rs`): UEFI через SimpleFileSystem, BIOS
через INT 13h.

1. `pending=1`, `tries>0`: когда запускается пункт `ospab`, который грузит `kernel=`, `tries`
   уменьшается и записывается до перехода в ядро, а в командную строку ядра добавляется
   `update_try=1`.
2. Ядро доходит до готовности консоли (строка `Console ready`) и из-за `update_try=1` пишет
   `pending=0 tries=0`. Обновление подтверждено.
3. `pending=1`, `tries=0`: за 2 загрузки ядро себя не подтвердило. Загрузчик пишет
   `pending=0 failed=1`, во всех пунктах (и их модулях) заменяет `kernel=` на `old=`, добавляет в
   командную строку `update_fallback=1` и показывает меню с причиной, например "System update
   1.1.0.191 failed to start 2 times. Booting the previous kernel 1.1.0.190". Таймер запускает
   прежнее ядро. Ядро тоже печатает предупреждение `System update`.
4. `failed=1` остаётся до следующего `tomato upgrade`, который пишет новое состояние. Пока
   состояние `pending` или `failed`, новое обновление не затирает `KERNEL.OLD`.

Правила и ограничения:

- Ручной запуск "ospab.os (previous)" новое ядро не подтверждает. Подтверждает только запуск с
  `update_try=1`. Правка командной строки клавишей `e` сохраняет `update_try=1`, потому что
  загрузчик добавляет его уже после правки.
- Если файла прежнего ядра нет, загрузчик сообщает об этом и снова пробует новое ядро.
- Если загрузчик не может записать `UPDATE.ST` (файловая система прошивки только для чтения),
  счётчик не уменьшается и автоматического отката нет. Пункт меню при этом работает.
- После отката меню остаётся на экране даже при `timeout = 0`.
- Сбой питания во время обновления оставляет в `KERNEL` либо старое, либо новое ядро, потому что
  переключение — это одна запись элемента каталога в 32 байта. Остаток `KERNEL.NEW` удалит
  следующее обновление.
- BIOS stage 2 пишется раньше stage 1 (в MBR). Если питание пропадёт между двумя записями, а новый
  stage 2 больше, чем ждёт старый stage 1, загрузка по BIOS не пойдёт, пока диск не восстановят с
  живого ISO. Загрузка по UEFI это не затрагивает.
