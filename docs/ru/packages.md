# Пакеты

## Работа с tomato

```
# tomato update              скачать индекс пакетов и проверить его подпись
# tomato search [текст]      искать по синхронизированному индексу
# tomato install calc          установить пакет с зависимостями
# tomato update && tomato upgrade             синхронизировать и обновить установленные пакеты
# tomato list               установленные пакеты (-Qi сведения, -Ql файлы)
# tomato remove calc          удалить пакет (отказ, пока от него зависит другой пакет)
# tomato install file.tmt      установить локальный файл пакета
```

Репозиторий по умолчанию — `https://tmt.ospab.org/x86_64/`. Чтобы взять другой, добавьте строки
`repo=<url>` в `/etc/tomato.conf` (для локальных тестов разрешён обычный `http://`).

## Как проверяются пакеты

- Индекс подписан Ed25519. Публичный ключ вшит в систему (`userland/tomato/repo_key.pub`).
  Индекс с неверной подписью отвергается, а сохранённый индекс проверяется заново при каждом
  использовании.
- Размер и SHA-256 каждого пакета записаны в подписанном индексе и проверяются до установки.
- `tomato remove` удаляет только те файлы, которые установил пакет.

Известный пробел: ничто не мешает подсунуть старый индекс, который был подписан правильно.

## Формат .tmt

Файл `.tmt` — это пакет: заголовок с именем, версией, архитектурой, зависимостями и описанием, а
за ним файлы с путями назначения и контрольными суммами. Пакет собирает хост-утилита `tmt` или
команда `tomato --tmt pack` внутри системы.

### Пакеты драйверов

Пакет с таблицей `[driver]` в манифесте — драйвер для менеджера устройств. Его файлы
устанавливаются в `/usr/lib/drivers/<имя>/`, а `tmt pack` добавляет туда `driver.conf`. Старые
пакеты и старый `tomato` это не затрагивает. Формат и правила:
[Драйверы в ring 3](dev/drivers.md).

```toml
[driver]
match = ["pci:8086:100e", "pci-class:02:00"]   # производитель:устройство или класс:подкласс (hex)
exec = "/usr/lib/drivers/e1000/drv-e1000"      # необязательно, по умолчанию первый файл
```

## Обновление системы

Пакет `ospab-base` — это сама система: ядро, загрузчик UEFI и загрузчик BIOS. Его версия — версия
ядра плюс номер сборки (`1.1.0.191`); `uname -a` показывает запущенную сборку. Файлы пишутся на
системный раздел EFI (ESP), а не в файловую систему в ОЗУ.

```
# tomato update
# tomato upgrade            покажет "system: 1.1.0.190 -> 1.1.0.191, reboot required"
# tomato upgrade -y         то же, без вопроса перед записью на ESP
# tomato install ospab-base
# tomato system             запущенная сборка, установленный системный пакет, счётчик загрузок
```

Что `tomato upgrade` делает с системным пакетом:

1. Находит ESP этой установки (установка на весь диск использует `\boot\`, установка рядом с
   другими системами — `\EFI\ospab\`). Если не может определить, с какого ESP загружена система,
   отказывается.
2. Печатает, какие файлы запишет, и спрашивает `[y/N]` (с `-y` не спрашивает).
3. Пишет `KERNEL.NEW` и новый загрузчик как `.NEW`, читает обратно и сравнивает.
4. Переключает одной записью элемента каталога на файл: `KERNEL` становится `KERNEL.OLD`, а
   `KERNEL.NEW` — `KERNEL`. Старый загрузчик остаётся как `.OLD`. Момента без загружаемого ядра
   не бывает.
5. Добавляет в `ospab.cfg` пункт "ospab.os (previous)" (грузит `KERNEL.OLD`), если его там нет.
6. Пишет счётчик загрузок `UPDATE.ST` (2 попытки). Новое ядро сбрасывает его, когда консоль
   готова. Если за две загрузки этого не произошло, загрузчик сам запускает прежнее ядро и
   объясняет причину в меню. См. [Загрузка](boot.md), раздел «Обновление системы».
7. При установке на весь диск с разделом BIOS boot пишет ещё новый stage 2 и код stage 1 в MBR
   (таблица разделов в MBR остаётся прежней).

Правила:

- Пишутся только перечисленные файлы. Других файлов на ESP (Windows, Linux) пакет не трогает.
- Живая система отказывается: обновление системы работает только на установленной системе.
- Системный пакет принимается только из подписанного репозитория. `tomato install file.tmt`
  его отклоняет, потому что собственная контрольная сумма файла подделку не заметит.
- `tomato remove ospab-base` отклоняется.
- Пока обновление не подтверждено (или после отката), новое обновление сохраняет последнее
  исправное `KERNEL.OLD`, а не затирает его неподтверждённым ядром.

Системный пакет — обычный `.tmt` с `kind=system` в метаданных. У его файлов нет путей, у каждого
своя роль: `esp:kernel` (обязательно), `esp:loader` (загрузчик UEFI), `esp:bios` (`bios.img`:
stage 1 со смещения 0, stage 2 со смещения 0x800). Старые пакеты без `kind` ставятся как раньше.
Шаблон манифеста лежит в `apps/pkg/ospab-base.toml`:

```toml
name = "ospab-base"
version = "1.1.0.191"
kind = "system"
[[files]]
src = "ospab_os"
dest = "esp:kernel"
```

Собирайте после `./build.sh`:

```
.\apps\build.ps1 -Base -Build 191 -Repo D:\ospab-projects\tmt-repo     # PowerShell
BASE=191 bash apps/build.sh repo /path/to/tmt-repo                      # Git Bash, WSL, Linux
```

`tmt pack <manifest> --set KEY=VALUE` заменяет `@KEY@` в манифесте. Шаблон использует
`@VERSION@`, `@KERNEL@`, `@LOADER@` и `@BIOS@`. Без `-Base` шаблон не пакуется. Ядро занимает
около 10 МиБ, поэтому системный пакет может быть до 24 МиБ и в кэше не хранится.

## Как написать программу

Программы — это бинарники Rust без `std` для цели `x86_64-unknown-oos`, слинкованные с рантаймом
liboos (`_start`, системные вызовы, куча, `print!`). SDK — рабочее пространство `apps/`, а
`apps/README.md` по шагам показывает, как сделать новую программу. Примеры: `hello-tmt`, `cowsay`,
`calc`.

Манифест пакета (`apps/pkg/calc.toml`):

```toml
name = "calc"
version = "0.1.0"
description = "Command-line calculator"
arch = "x86_64"
depends = []

[[files]]
src = "../target/x86_64-unknown-oos/release/calc"
dest = "/usr/bin/calc"
```

Поднимайте `version` при каждом изменении: опубликованные пакеты кешируются как неизменяемые.

## Сборка и публикация репозитория

Windows (PowerShell 7):

```
.\apps\build.ps1 -Repo D:\ospab-projects\tmt-repo -Upload user@server
```

Git Bash, WSL или Linux:

```
bash apps/build.sh repo /path/to/tmt-repo
```

Оба варианта собирают программы, упаковывают их, добавляют в репозиторий и строят индекс. Потом
индекс подписывается ключом `%USERPROFILE%\.ospab\tmt.key` (в WSL задайте
`USERPROFILE=/mnt/c/Users/<вы>`), и подпись проверяется ключом, вшитым в систему. Выгружайте
сначала пакеты, потом `index`, последним `index.sig`.

Настройка сервера (nginx, HTTPS через certbot) описана в
[tools/tmt/deploy/README.md](../../tools/tmt/deploy/README.md). Сделайте резервную копию
приватного ключа. Если он потеряется, придётся создать новую пару ключей и выпустить новый образ
системы.
