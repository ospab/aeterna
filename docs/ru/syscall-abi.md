# Системные вызовы: объекты, дескрипторы, IPC

Реализация: `core/object.rs` (логика), `core/syscall/objects.rs` (обвязка), обёртки для программ —
`user/liboos/src/ipc.rs` (IPC), `user/liboos/src/mem.rs` (память), `user/liboos/src/hw.rs`
(прерывания, порты, DMA). Остальные вызовы (write, mmap, ...) — в `core/syscall/mod.rs`.

## Соглашение

`SYSCALL`: номер в `RAX`, аргументы `RDI, RSI, RDX, R10, R8`, результат в `RAX`.
`RCX` и `R11` портятся. Результат < 0 — ошибка:

| код | имя | смысл |
|---|---|---|
| -1 | InvalidSyscall | нет такого вызова |
| -2 | PermissionDenied | у дескриптора нет нужного права |
| -3 | InvalidArgument | неверный аргумент (длина > 128, повтор дескриптора, ...) |
| -5 | Busy | очередь канала полна |
| -6 | OutOfMemory | нет страниц, нет свободного диапазона адресов, таблица объектов полна |
| -7 | NotSupported | объект этого не умеет (например, `mem_phys` у обычной памяти) |
| -9 | NoSuchProcess | |
| -10 | BadAddress | указатель вне пространства процесса |
| -11 | BadHandle | значения нет в таблице (не выдавалось, закрыто, устарело) |
| -12 | WrongType | дескриптор указывает на объект другого типа |
| -13 | PeerClosed | другая сторона исчезла (канал закрыт, Reply выброшен) |
| -14 | TableFull | таблица дескрипторов процесса полна (256) |
| -15 | Timeout | вышло время ожидания |

## Дескрипторы и права

Дескриптор — `u32`: `(поколение << 16) | (слот + 1)`; 0 недействителен. Закрытый слот получает
новое поколение, поэтому старое значение отвергается (`BadHandle`), даже если слот занят снова.
Дескрипторы, выданные ядром до запуска программы, получают значения 1, 2, 3... в порядке выдачи.

Права: `READ`=1 (принять, ждать), `WRITE`=2 (вызвать, отправить, сигналить, ответить, убить),
`DUP`=4 (можно размножить), `TRANSFER`=8 (можно передать в сообщении). У объектов памяти ещё `MAP`=16 (можно отобразить),
`EXEC`=32 (можно отобразить исполняемой; пока никакой вызов его не выдаёт) и `PHYS`=64 (можно узнать
физический адрес). Копия может только терять права.

Объекты: **Process**, **Thread** (пока один поток на процесс), **Channel**, **Notification**,
**Reply** (право ответить на один вызов; создаётся ядром при `call`, выдаётся получателю в `recv`), **MemoryRegion**, **MmioRegion**, **Interrupt**, **IoPortRange**,
**Resource** (см. ниже).
Объект живёт, пока есть хотя бы один дескриптор или сообщение в пути. При завершении процесса все его
дескрипторы закрываются, объекты освобождаются, ожидающие просыпаются.

## Сообщение

160 байт: `tag: u64`, `len: u32` (≤ 128), `nhandles: u32` (≤ 4), `handles: [u32; 4]`, `data: [u8; 128]`.
Дескрипторы в сообщении **переносятся** (удаляются у отправителя, нужно право `TRANSFER`), у получателя
появляются новые значения; на выходе `handles[]` содержит значения в таблице получателя.

## Вызовы

| № | вызов | аргументы → результат |
|---|---|---|
| 200 | handle_close | h → 0 |
| 201 | handle_dup | h, rights → новый h (нужно DUP) |
| 202 | handle_info | h → тип \| rights<<8 (1 Process, 2 Thread, 3 Channel, 4 Notification, 5 Reply, 6 MemoryRegion, 7 MmioRegion, 8 Interrupt, 9 IoPortRange, 10 Resource) |
| 210 | channel_create | → h (все права) |
| 211 | ipc_call | ch (WRITE), req*, reply* → reply.len. Спит, пока сервер не ответит |
| 212 | ipc_send | ch (WRITE), msg* → 0. Односторонне, не блокирует |
| 213 | ipc_recv | ch (READ), msg*, timeout → handle Reply (0 для односторонних). Спит, пока нет запроса |
| 214 | ipc_reply | reply_h (WRITE), msg* → 0. Дескриптор Reply расходуется |
| 220 | notify_create | → h |
| 221 | notify_signal | h (WRITE), bits → 0 (OR в 32-битное слово) |
| 222 | notify_wait | h (READ), timeout → bits (≠0), слово обнуляется |
| 230 / 231 | process_self / thread_self | → h (все права) |
| 232 | process_wait | h (READ), code*, timeout → 0, код выхода записан по `code*` |
| 233 | process_kill | h (WRITE) → 0 (себя убить нельзя, есть exit) |
| 240 | mem_create | size → h (READ\|WRITE\|MAP\|DUP\|TRANSFER); страницы обнулены, размер округляется вверх, ≤ 64 МиБ |
| 241 | mem_map | h (MAP+READ, +WRITE, +EXEC), hint, prot → адрес отображения |
| 242 | mem_unmap | addr (ровно то, что вернул mem_map) → 0 |
| 243 | mem_create_contig | resource (DMA, WRITE), size → h (как у mem_create + PHYS); непрерывно, ≤ 4 МиБ |
| 244 | mem_phys | h (PHYS) → физический адрес (непрерывные и MMIO-области) |
| 245 | mem_size | h → размер в байтах |
| 250 | irq_bind | irq (READ), notification (WRITE), bits → 0 |
| 251 | irq_ack | irq (WRITE) → 0; снимает маску с линии |
| 252 | ioport_enable | h (READ+WRITE) → 0; порты становятся доступны для IN/OUT |
| 253 | ioport_disable | h → 0 |

`timeout` — в тиках 100 Гц, 0 = ждать бесконечно. Ожидание не крутит цикл: задача получает состояние
Waiting, CPU уходит в HLT, будит другая сторона (или срок). Если у канала не осталось дескрипторов с
`READ`, он закрывается: все ждущие `call` получают `PeerClosed`.

## Разделяемая память (этап 2, пункт 12)

**MemoryRegion** — набор физических страниц, которым владеет объект ядра. `mem_create` создаёт
обычную (анонимную) область; дескриптор передаётся другому процессу в сообщении (обычно копия с
меньшими правами). Каждый процесс отображает её через `mem_map` и видит записи другого.

- `prot` у `mem_map`: `READ`=1, `WRITE`=2, `EXEC`=4. `READ` обязателен; `WRITE|EXEC` вместе
  запрещено (W^X), ответ `InvalidArgument`. Нужные права: `MAP`+`READ`, для записи ещё `WRITE`, для
  исполнения — `EXEC`. **По умолчанию страницы неисполняемые (NX)**; `EXEC` пока не выдаёт ни один
  вызов, поэтому разделяемая память не бывает исполняемой. Процесс, пишущий через отображение только
  для чтения, получает #PF и завершается ядром.
- `hint` зарезервирован (передавайте 0): адрес выбирает ядро в области mmap процесса.
- Отображается вся область; `mem_unmap` принимает ровно адрес, который вернул `mem_map`
  (частичное снятие не поддерживается).
- Отображение держит свою ссылку: закрытие дескриптора его не снимает. Страницы освобождаются,
  когда закрыт последний дескриптор **и** снято последнее отображение. При завершении процесса
  дескрипторы закрываются, отображения снимаются.
- Удалены: старый механизм SMR (вызовы 120–122, сырые физические адреса без владельца),
  `dma_alloc` (130), отдававший физический адрес в ring 3, прямой ввод-вывод в порты (60/61),
  `irq_wait` (62) и `vfs_register` (100).

**DMA.** `mem_create_contig(resource, size)` выделяет физически непрерывные страницы, у дескриптора
есть `PHYS`; `mem_phys` возвращает адрес, который драйвер пишет в устройство. Это может только процесс
с дескриптором **Resource** вида DMA (с `WRITE`); копию без `PHYS` можно отдать клиентам, чтобы они не
узнали адрес.

## Оборудование как дескрипторы (этап 2, пункт 13)

Объекты Interrupt, IoPortRange, MmioRegion и Resource нельзя создать системным вызовом. Их создаёт
только привилегированный корень (сейчас — загрузочный код ядра, `core::object::kernel_new_*`; потом
`seed`) и передаёт драйверу как начальные дескрипторы (`core::elf::spawn_with_handles`).

- **Interrupt** — линия IRQ контроллера 8259, сейчас только 3, 6 или 8 (их не использует ни один
  драйвер ядра); одна линия — один объект; MSI пока нет. После `irq_bind` каждое прерывание
  **маскирует линию**, делает OR `bits` в уведомление и будит ждущего; EOI посылает ядро. Драйвер
  обслуживает устройство и вызывает `irq_ack` — маска снимается. С создания и до первого `irq_ack`
  линия замаскирована; при удалении объекта маскируется снова.
- **IoPortRange** — порты `[base, base+count)`. Механизм — **карта разрешений ввода-вывода в TSS**.
  `IOPL` остаётся 0; `ioport_enable` строит карту процесса (бит на порт, 1 = запрещён), и планировщик
  копирует её в TSS при переключении на этот процесс (только используемые байты и только если
  загружена карта другого процесса). У процессов без портов карта выключена (`iopb_offset` за
  пределом TSS): любой IN/OUT даёт #GP, и процесс завершается. Сам доступ к порту ничего не стоит
  (без системного вызова на каждый доступ). Как и отображение, включённый диапазон держит ссылку и
  действует до `ioport_disable` или завершения процесса.
- **MmioRegion** — физический диапазон устройства (например, BAR PCI); `mem_map` работает с ним как с
  MemoryRegion, но страницы отображаются **без кэширования** (PCD|PWT) и никогда не освобождаются.
  Обычную память, которой управляет аллокатор страниц, нельзя выдать как MMIO.
- **Resource** — право создавать особые объекты; вид DMA разрешает `mem_create_contig`.

Тесты: параметр ядра `selftest=mem` (`user/memtest`, `user/uartdrv`). Драйверу COM2 (`uartdrv`) нужен
второй последовательный порт в QEMU: `-serial file:com1.log -serial file:com2.log`.
