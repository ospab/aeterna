# Графическая сессия: архитектура

Графика — это крейт `gui/` (`oos-ui`, `no_std` + `alloc`). Всё рисуется программно в поверхности
ARGB8888. Пути через GPU нет. Ядро только копирует готовые пиксели во фреймбуфер.

Запуск — командой `desktop` или загрузкой с параметром ядра `session=desktop`. Выход (Log out в
меню приложений) возвращает в консоль.

## Слои

| Слой | Модули | Задача |
|---|---|---|
| Пиксели | `surface`, `canvas`, `blend`, `shadow`, `damage` | Поверхности, отсечение, сглаженные фигуры, мягкие тени, списки изменённых областей |
| Текст | `text`, `fonts` | Растеризатор fontdue, кеш глифов, кернинг, встроенные Inter и JetBrains Mono |
| Дизайн | `theme`, `icons` | Токены (цвета, скругления, отступы, шкала шрифтов, анимации), векторные иконки |
| Виджеты | `ui`, `menu` | Дерево виджетов, раскладка, ввод, фокус, перерисовка по виджетам |
| API приложений | `app` | `Application`, `Ctx`, `WindowSpec`, диалоги, таймеры, буфер обмена, `Platform` |
| Окно | `window` | Клиентская часть окна: поверхность, заголовок, кнопки, связка с протоколом |
| Протокол | `proto` | Сообщения между приложениями и оконным менеджером |
| Оконный менеджер | `desktop`, `session` | Композитор, порядок окон, фокус, верхняя панель, док, меню, Alt+Tab |

Главное разделение: **приложения используют только `app`** (и типы виджетов, которые он
реэкспортирует). Оконный менеджер (`desktop`) и цикл сессии в коде приложений не встречаются.

## Процессы сейчас

Всё выполняет один поток ядра (`src/userspace/axon/desktop/`):

```
клавиатура / мышь ──> Session::input ──> Desktop (WM) ──ToClient──> Bus
                                                                     │
                          AppHost (по одному на приложение) <────────┘
                          Application::event / tick
                                   │ ToServer (Create, Damage, ...)
                                   v
                              Bus ──> Desktop::apply ──> композиция ──> фреймбуфер
```

Каждый кадр (`Session::frame`):

1. Ввод устройств идёт оконному менеджеру. Рамки окон, фокус и сочетания клавиш он обрабатывает
   сам; остальное становится `ToClient::Input` для окна под указателем или окна с фокусом.
2. Каждый `AppHost` забирает сообщения своих окон, отдаёт их дереву виджетов и вызывает
   `Application::event` для того, что дерево не обработало.
3. Выполняются таймеры и `Application::tick`; каждое окно перерисовывает изменённые
   прямоугольники и отправляет `ToServer::Damage`.
4. Оконный менеджер применяет запросы, собирает только изменённые прямоугольники экрана и
   возвращает их; ядро копирует эти прямоугольники во фреймбуфер.

Если ничего не изменилось, кадр почти ничего не стоит, и цикл выполняет `hlt`.

## Протокол оконного менеджера (`gui/src/proto.rs`)

От клиента к серверу (`ToServer`):

| Сообщение | Смысл |
|---|---|
| `Create { id, title, icon, size, min, resizable, surface }` | Показать окно. Поверхность выделяет клиент, и пишет в неё только он |
| `SetTitle { id, title }` | Новый заголовок |
| `Damage { id, rects }` | Эти прямоугольники (в координатах окна) изменились |
| `BeginMove { id }` | Начать перетаскивание (нажатие на заголовок) |
| `Minimize { id }`, `ToggleMaximize { id }` | Попросить сменить состояние |
| `SetCursor { id, shape }` | Форма указателя над клиентской областью |
| `Activate { id }` | Поднять наверх и дать фокус |
| `Destroy { id }` | Окна больше нет |

От сервера к клиенту (`ToClient`):

| Сообщение | Смысл |
|---|---|
| `Configure { id, w, h }` | Сервер выбрал новый размер. Клиент меняет размер поверхности, пересчитывает раскладку и шлёт полный `Damage` |
| `Input { id, ev }` | События указателя и клавиш в координатах окна (`Event`) |
| `Focus { id, focused }` | Изменился фокус клавиатуры |
| `CloseRequested { id }` | Нажата кнопка закрытия, Alt+F4 или закрытие из дока |

Правила для любого транспорта:

* Пиксели принадлежат клиенту. Сервер их только читает, и гарантированно актуальны лишь
  прямоугольники последнего `Damage`.
* Геометрия принадлежит серверу: положение, порядок, размер, фокус. Клиент может только просить.
* Заголовок окна рисует клиент (`window.rs`), поэтому вид окна не зависит от сервера. Сервер
  рисует тень, композицию без рамок и элементы оболочки.

Транспорт внутри ядра — `proto::Bus` (две очереди), а `SharedSurface` — это
`Rc<RefCell<Surface>>`.

## Оконный менеджер

Реализован в `gui/src/desktop.rs`.

| Возможность | Поведение |
|---|---|
| Перемещение | Тянуть за заголовок. Двойной щелчок разворачивает |
| Изменение размера | Тянуть за любой край или угол (меняется курсор); минимальный размер из `WindowSpec` |
| Свернуть / развернуть / закрыть | Три круглые кнопки слева в заголовке |
| Фокус и подъём | Щелчок, иконка в доке или `Activate` |
| Alt+Tab | Переключатель; держать Alt, Tab листает (Shift — назад), отпустить — переключиться, Esc — отмена |
| Alt+F4 | Отправляет `CloseRequested` окну с фокусом |
| Meta (клавиша Windows) | Открывает меню приложений |
| Верхняя панель | Кнопка меню, имя активного приложения, сеть и OSTP, громкость, часы |
| Док | Иконка на каждое закреплённое приложение; точка — приложение запущено; щелчок поднимает или запускает |
| Перерисовка | Только изменённые прямоугольники: перемещение окна добавляет старую и новую область |

Часы берут часовой пояс из `/etc/timezone` (`UTC+3`, `UTC-5`, `UTC+5:30`).

## Стоимость кадра

Программная отрисовка с учётом изменённых областей. При выходе сессия печатает тайминги (и в
последовательный порт). Замеры в QEMU TCG без KVM (медленный эмулированный процессор), 1280x800,
пять окон:

| Показатель | Значение |
|---|---|
| Инициализация сессии (шрифты, тема, композитор) | 209 мс |
| Первый кадр | 97 мс |
| Полная пересборка экрана | 28 мс |
| Средний кадр при работе (487 кадров) | 10,9 мс |
| Средняя перерисованная площадь | 127 тыс. пикселей (12 % экрана) |

На хосте (нативно, `gui/examples/mockups.rs`) первый кадр занимает 3,2 мс, полная пересборка —
1,7 мс. На реальном железе ожидаются цифры, близкие к хостовым.

## Перенос композитора в ring 3

Ничему в `oos-ui` ядро не нужно. Меняются такие части:

| Сейчас | В ring 3 |
|---|---|
| Очереди `Bus` | IPC-канал на каждого клиента плюс слушающий канал сервера (`user/liboos/src/ipc.rs`). Сообщения сериализуются: это небольшие перечисления плюс список прямоугольников |
| `SharedSurface = Rc<RefCell<Surface>>` | Дескриптор области общей памяти (`user/liboos/src/mem.rs`). Клиент отображает её на чтение и запись, сервер — копию дескриптора только на чтение. `Create` несёт дескриптор |
| `Session::pump` по очереди вызывает `AppHost` | Сервер ждёт на своих каналах; каждый процесс-клиент крутит свой цикл `AppHost` и блокируется на своём канале |
| `Platform` передаёт вызовы в VFS | `Platform` реализован через системные вызовы liboos (файлы, запуск) |
| Клавиатура и мышь читаются в цикле ядра | Драйвер ввода в ring 3 (дескрипторы портов и прерываний уже есть) пересылает события серверу |
| Копирование во фреймбуфер в `Fb::present` | Сервер отображает фреймбуфер как область памяти по ресурсу MMIO |

Клиентская сторона уже отделена: `AppHost` только производит сообщения `ToServer` и потребляет
сообщения `ToClient`. В ring 3 `AppHost` заменяет внутрипроцессный `Bus` каналом, и больше в
приложении ничего не меняется. `apps/hello-gui` уже сегодня собирается для `x86_64-unknown-oos` и
работает с сессией внутри своего процесса; это шаблон для переноса.

Что осталось: кодирование сообщений, дескриптор поверхности в `Create`, драйвер ввода и точка
входа клиентской библиотеки (`oos_ui::run(app)`), которая подключается к серверу.

## Сборка и проверка

| Задача | Команда |
|---|---|
| Проверка библиотеки на хосте | `cargo check --manifest-path gui/Cargo.toml --features std --examples` (запускать вне корня репозитория, иначе `.cargo/config.toml` ядра включит `build-std`) |
| Обновить PNG-макеты | `cargo run --manifest-path gui/Cargo.toml --features std --example mockups` (пишет `gui/mockups/*.png`) |
| Сборка для ring 3 | `cd apps && cargo +nightly build --release -p hello-gui` |
| Ядро с рабочим столом | `./build.sh kernel` |

Макеты рисуются той же сессией, тем же оконным менеджером и теми же виджетами, что и рабочий
стол в ядре.
