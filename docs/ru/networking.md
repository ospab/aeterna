# Сеть и OSTP

## Сетевой стек

При загрузке первая поддерживаемая сетевая карта поднимается и настраивается по DHCP. Если DHCP
не ответил, адрес становится link-local `169.254.1.1`, а лог загрузки показывает предупреждение.

Протоколы: Ethernet, ARP, IPv4, ICMP, UDP, TCP, DHCP, DNS (с `/etc/resolv.conf`, по умолчанию
Cloudflare и Google), NTP и клиент TLS 1.3, которым пользуются `curl`, `tomato` и `ostp`.

```
# ip addr          адреса (lo и eth0), запасной адрес без DHCP помечен
# ip link          состояние линка, драйвер, счётчики пакетов и байтов
# ip route         маршрут по умолчанию, подключённая подсеть, loopback
# ping -c 3 1.1.1.1
# nslookup ospab.org
# curl https://ipinfo.io
# ntpdate          установить время по NTP
# netdiag          диагностика сетевой карты и список PCI
```

Поддерживаемые карты перечислены в разделе [Оборудование](hardware.md).

## OSTP

[OSTP](https://github.com/ospab/ostp) — скрытый транспорт ospab. В ospab.os встроен клиент,
команды которого повторяют клиент `ostp` для Linux.

```
# ostp import ostp://KEY@host:port          сохранить ссылку
# ostp import https://host/sub/TOKEN        сохранить подписку (все её серверы)
# ostp sub                                  показать подписку: серверы, трафик, обновление
# ostp sub update                           обновить её
# ostp list                                 сохранённые серверы; * — выбранный
# ostp use 2                                выбрать другой сервер (переподключит, если подключены)
# ostp connect                              подключиться к выбранному серверу
# ostp status                               состояние сессии, транспорт, счётчики
# ostp ping -c 3                            ping через туннель
# ostp dns example.com                      DNS через туннель
# ostp get example.com /                    HTTP-запрос через сервер
# ostp close                                отключиться
# ostp check                                проверить сохранённую конфигурацию
# ostp gk -n 2                              сгенерировать ключи доступа
```

Конфигурация хранится в `/etc/ostp/config.json`; на установленной системе она переживает
перезагрузку, когда записана на диск (`sync` или автоматически через несколько секунд).

Транспорты: **UDP** и **UoT** (UDP поверх TCP). Ссылки, которым нужен TLS, помечаются как
неподдерживаемые. Пока консоль ждёт ввода, она поддерживает установленную сессию keepalive-пакетами;
если сессия умерла, следующая команда `ostp` переподключится.

Случайные числа для рукопожатия берутся из инструкции процессора RDRAND. На процессоре без
RDRAND `connect` отказывает без флага `--weak-rng` (в QEMU используйте `-cpu max`).

Набирать длинную ссылку руками не нужно: в VMware используйте Ctrl+V или `ostp import $(clip)`,
см. [Оболочка и утилиты](shell.md).

Пока нет: маршрутизации всего трафика системы через туннель (туннельного сетевого интерфейса).
